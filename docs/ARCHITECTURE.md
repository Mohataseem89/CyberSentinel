# Architecture

## Overview

CyberSentinel is split into a React/Vite frontend and a Flask backend. PostgreSQL stores users, reviewed feedback, and explicitly retained owner-scoped scan history. The phishing model is loaded from versioned local artifacts generated by an offline training pipeline.

```text
Browser
  |
  | HTTPS
  v
React/Vite frontend
  |
  | JSON / multipart API
  v
Flask backend
  |-- URL normalization / validation
  |-- lexical feature extraction
  |-- calibrated ML predictor
  |-- optional VirusTotal reputation lookup
  |-- conservative risk engine
  |-- JWT auth / owner-scoped history
  |-- feedback review
  v
PostgreSQL
```

## URL scan flow

1. The frontend submits an HTTP/HTTPS URL to `POST /analyze`.
2. `ScanRequest` and the URL normalizer validate and canonicalize the input.
3. The analyzer extracts local URL features. The target webpage is not fetched or executed.
4. The versioned model and calibrator produce an ML risk signal.
5. If configured, VirusTotal provides independent reputation evidence.
6. `RiskEngine` combines available evidence conservatively.
7. The response contains a verdict, optional risk score, confidence label, evidence, limitations, indicators, and recommendations.
8. Scan history is written only when the user is authenticated and the request explicitly sends `X-Retain-Scan: true`.

## Trust boundaries

- **Browser ↔ frontend:** untrusted user input.
- **Frontend ↔ backend:** untrusted network/API boundary; all inputs must be validated server-side.
- **Backend ↔ VirusTotal:** external third-party trust boundary and availability/privacy dependency.
- **Backend ↔ PostgreSQL:** privileged data boundary; use least-privilege credentials and encrypted transport in production.
- **Offline training pipeline:** separate trust boundary from the online runtime. Training artifacts must be reviewed before promotion.

## Deliberately disabled behavior

- Remote target-page fetching is disabled.
- Legacy global analytics blueprint registration is disabled because the old queries were not owner-scoped.
- API-triggered model retraining/reloading must not be treated as an automatic production training path.

## Scaling considerations

The built-in fixed-window limiter stores counters in process memory. Multiple backend replicas would each have independent counters, so production horizontal scaling requires a shared rate-limit backend. Database connection pooling, structured logging, centralized metrics, backup policy, and secret management are deployment responsibilities.
